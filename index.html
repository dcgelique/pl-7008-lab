Lab 01 · 30 minutes maximum

Get started: US Government Benefits Assistant

Concepts: Environment, Standard Harness, manual creation, instructions, knowledge and testing

Understand it first

The Studio home page and agent runtime are separate choices. In this workshop, the new Studio entry point opens Standard Harness agents. They support native Topics, typed variables, entities and the Test your agent pane. A Copilot Studio trial supports creation and testing, but not agent publishing.

Access fallback: Review the provided instructions and write expected replies to both tests. Record access or indexing limitations. This is design review, not a live agent test.

Spend at most 3 minutes on an access or missing-control issue, then take this route. Do not purchase a license, enable pay-as-you-go, publish, or wait for provisioning.

Open a Standard Harness draft · 5 min

  • Open the new Copilot Studio home page and select your workshop environment.
  • Use Other ways to build to open agents powered by the Standard Harness.
  • Choose Create blank agent or open the facilitator-provided Standard Harness draft.
  • Do not choose the GitHub Copilot harness agent card.
  • Confirm the agent exposes Topics and the topic authoring canvas.
  • Navigation labels can vary; the agent runtime is Standard Harness even when its authoring surface resembles the earlier experience.

Lab 02 · 30 minutes maximum

Manage Topics

Concepts: Native topics, triggers, question/message nodes, conditions, system topics

Understand it first

A topic is an authored conversation path. Its trigger identifies when it starts; question nodes collect values; messages present information; conditions branch on values. These are native Standard Harness controls, not skills. Generative orchestration can choose a topic by its description; classic orchestration uses trigger phrases.

Access fallback: Sketch the same native node sequence and annotate both paths with Category and Receipt. Record this as topic design review; no skill-based substitute is claimed.

Spend at most 3 minutes on an access or missing-control issue, then take this route. Do not purchase a license, enable pay-as-you-go, publish, or wait for provisioning.

Lab 03 · 30 minutes maximum

Work with entities and variables

Concepts: Number entity, choice values, typed topic variables, scope, conditions and variable output

Understand it first

An entity recognizes values from the user response. A variable stores a typed value. Topic variables are local to the topic; Global variables are available to other topics in the same agent conversation. Global does not mean shared between all users. Use inserted variable tokens and matching types in conditions.

Access fallback: Complete a Field / Entity / Type / Scope table and trace -10 and 800 through the condition. The summary placeholders are authoring cues: replace each with the UI’s actual variable token.

Spend at most 3 minutes on an access or missing-control issue, then take this route. Do not purchase a license, enable pay-as-you-go, publish, or wait for provisioning.

Inspect existing types · 5 min

  • Open Prepare Expense Draft from Lab 02.
  • Select the Category and Receipt variables in their question nodes and inspect their types and scope.
  • They are choice values from the question options.
  • Keep both Topic scoped for this lab; discuss when Global scope would be appropriate for a second topic.

Add a typed amount · 12 min

  • In the Receipt=Yes branch, insert a Question before the final message: “What is the amount in PHP?” Set Identify to Number and Save user response as Amount.

  • Move the final draft message under that valid branch.

    Invalid-branch message
    Please restart the draft and enter an amount greater than zero.

    Purpose question
    What is the business purpose of this expense?

    Valid-branch summary layout

Test validation and scope · 10 min

  • Start a new test session, choose Meals/Yes and enter -10; expect the invalid branch.
  • Start another session with Meals/Yes, 800 and Customer meeting; expect the summary with all values.
  • Open the variables panel to inspect actual values if available.
  • Start another new session and confirm old topic values are not reused.
  • Standard Number recognition may accept number words; inspect the resulting numeric value instead of assuming words always fail.

Checkpoint · 3 min

  • Record Amount’s numeric type, Category’s choice type and scope.
  • Explain the difference between entity recognition and variable storage.
  • If changing a variable scope later, update references and retest.

Expected outcome

    Read-only tool contract
    Name: GetExpenseClaim
Purpose: Read the provided training claims and return exactly one matching ClaimId. Never create, update, approve, pay, or delete.
Input: claimId (required text, for example EXP-002)
Output: found (Boolean), claimId, category, amount (number), status (text)

Failure: return a clear error; agent must say lookup failed and must not invent status.
    Agent flow contract for design review
    Name: CheckExpenseDraft
Trigger: When an agent calls the flow
Inputs: category (text), amount (number), receipt (Boolean), businessPurpose (text)
Validation: supported category; positive numeric amount; nonempty purpose; receipt explicitly supplied.
Branch order:
1. Invalid or missing required input -> Needs information
2. receipt=false -> Needs receipt
3. amount > category limit (Meals 800 / Travel 5000) -> Needs review
4. Otherwise -> Ready for review
Output: status (text), reason (text), limit (number or null)
No external writes. Ready for review is not approval.

Standard Harness concept reference
Topics and orchestration
Topics contain authored triggers and nodes. Questions collect input, messages present content, conditions branch, redirects call another topic and end nodes finish paths. Generative orchestration can select topics using their descriptions; classic orchestration uses trigger phrases. Standard Harness does not mean classic orchestration must be selected.
Entities and variables
Entities recognize values; typed variables store them. Topic scope is local to a topic; Global scope allows other topics in the same conversation to access values. Changing scope can require updating formula references. Choice values and numbers must be compared with matching types. Adaptive Cards are richer structured presentations supported in suitable nodes/channels; this timed lab uses inserted variables in a message.
System topics and knowledge
Conversation Start opens a session, Fallback handles unmatched requests, and Escalate supports escalation behavior when configured. A referral message alone does not configure live human handoff. Conversational boosting and Create generative answers can answer from knowledge where available. Source readiness, permissions and source selection affect grounding; an instruction is not a hard data-access control.
Tools and agent flows
Tools perform operations. Agent flows supply configured actions with typed inputs and outputs. At agent level orchestration selects a tool; in a topic the call sits at a defined node. An agent-callable flow needs the appropriate trigger, response, publication and supported runtime settings. Because publishing is outside these labs, flow logic is reviewed with a contract and local checker rather than attached as an unpublished tool.
Environment and lifecycle
Environments separate workspaces and access. Solutions group supported components and publishers set naming prefixes. Dataverse for Teams is Teams-scoped; full Dataverse has a different environment and capability model. Deployment, authentication, channels, production analytics and automated evaluations are discussion concepts here. No deployment, voice channel or live handoff is configured.
Testing
Use Test your agent with fresh sessions. Track between topics follows authored nodes; an activity map helps inspect generative decisions where available. Inspect actual variable values, source references and tool outcomes. Keep pass/fail evidence and rerun a changed scenario plus one previously passing case. Production analytics and real run history require actual usage; the local checker is not run history.
